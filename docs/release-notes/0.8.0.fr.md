# Chaosfolk 0.8.0 alpha

Tu peux maintenant choisir la profondeur d'un audit de ton produit, retirer des
tests et suivre leur avancement dans un tableau de bord local. Cette version
corrige aussi l'arrêt des scans et la protection des rapports à partager.

## Choisir les tests et fixer des limites

Rapide sélectionne les vérifications les plus prioritaires, Standard ajoute
davantage de cas et Approfondi sélectionne les 116 tests du catalogue. Chaque
niveau porte sur l'ensemble du produit. Chaosfolk adapte les tests aux fonctions
découvertes dans ton application ; une vérification qui exige un compte ou un
outil manquant reste indiquée comme bloquée.

Tu peux décocher les tests que tu souhaites retirer. Tes choix restent enregistrés
quand tu changes de niveau. Pendant le scan, tu suis les résultats et le temps
écoulé, avec des limites de durée, d'actions et de navigateurs ouverts. La limite
de navigateurs est fixée à six par défaut.

![Réglages du scan dans le tableau de bord Chaosfolk.](https://raw.githubusercontent.com/loukan42/chaosfolk/v0.8.0/assets/audit-scan.gif)

La consommation d'IA s'affiche lorsque ton assistant de code fournit les mesures.
Sinon, elle reste indiquée comme indisponible. L'actualisation du tableau de bord
ne fait aucun appel à l'IA.

## Garder le contrôle du scan

Le bouton Arrêter reste accessible pendant une sauvegarde et en bas de la liste
des tests. Une demande de démarrage retardée ne peut plus relancer un scan que
tu viens d'arrêter. À la reprise, les outils interrompus reviennent dans la liste
du travail à faire, avec leurs observations conservées.

Tes limites restent dans le formulaire si une sauvegarde échoue, même après
rechargement. Les modifications de champs différents dans deux onglets ne se
remplacent plus. Chaosfolk ferme les navigateurs des utilisateurs indépendants
terminés avant d'ouvrir le lot suivant, ainsi que les programmes externes à la fin
des tests.

Une demande déjà envoyée à l'IA peut encore consommer après l'arrêt. Son annulation
dépend de l'assistant qui exécute les agents.

## Comprendre et partager les résultats

Le rapport distingue les tests terminés, retirés, bloqués et encore à faire. Un
audit incomplet porte une note provisoire ; avant le premier résultat, aucune
note chiffrée n'est affichée. Les agents conservent toutes les pages qu'ils
découvrent en parallèle.

Les copies à partager retirent les observations brutes et les diagnostics de
rejeu qui peuvent contenir des valeurs saisies. Les détails restent dans la
session privée, avec des droits d'accès restreints. L'export d'un scénario est
refusé lorsqu'il contient un contrôle sensible ou un lien d'authentification
reconnu. Les anciens scénarios restent à relire avant de les partager.

Les grands rapports chargent leurs détails à la demande. Plusieurs traitements
utilisent le disque pour limiter la mémoire occupée par les longues sessions.

## Vérifier qu'un problème se reproduit

Tu peux rejouer un parcours sur des données de test remises dans un état vérifié
avant chaque essai et le comparer à un parcours de référence. Le rapport affiche
le nombre d'échecs parmi les essais valides : un échec sur cinq reste distinct
de cinq échecs sur cinq. Une erreur d'exécution compte comme un essai invalide.

Les sondes de pages et les contrôles d'accessibilité refusent désormais les
redirections, même sur le même site. Il faut leur fournir l'adresse finale
autorisée ; sinon, le résultat reste non concluant.
